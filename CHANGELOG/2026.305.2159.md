# 2026.305.2159 — feat(skill): give the clawhub skill dispatcher triggers

## Summary

A corpus skill with no `triggers:` is unreachable: the R0 dispatcher emits one row per triggers-bearing skill, so an untriggered skill silently has no routing at all (record: opencharly/marketplace#511).

`openclaw:clawhub` is the ClawHub CLI candy's owning skill. It carried no `triggers:` and no `category:`, so `DISPATCHER.md` had no row for it. This adds both, and the row now exists — proven by RUNNING the generator, not by describing it (below).

**This head is a re-derivation, not the original branch.** The branch had gone `CONFLICTING` against `main` because main has since moved the skill BODY out of `charly.yml` into `.agents/skills/clawhub/SKILL.md`, and this branch still carried the old inline `content:` block. The merge (one new merge commit — no rebase, no force-push) resolves `charly.yml` by keeping exactly the two additions this change makes and dropping the stale body copy; the skill text stays owned by `.agents/skills/clawhub/SKILL.md` and is untouched here.

One deliberate correction against the original body: the category is **`commands`**, not `images`. The dispatcher's categories name what a reader is trying to do — `commands` is for a CLI/verb surface, which is what ClawHub is, and it is the classification the sibling case uses (`layer-crabbox`'s `crabbox-cli`). The original rationale ("reached when composing the CLI into an image") describes how the candy ships, not what the skill answers.
